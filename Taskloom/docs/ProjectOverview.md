# Taskloom

## Краткое описание

Taskloom - персональное Windows desktop-приложение для планирования и организации повседневной деятельности. Приложение строится вокруг календаря и работы с разными типами записей, привязанными к датам.

## Цели проекта

- Создать быстрый и удобный personal organizer для повседневного использования.
- Построить расширяемую модель записей, не сводя систему к обычному todo list.
- Обеспечить последовательное развитие MVP без архитектурного перегруза.

## Стек

- C#
- .NET 10
- WPF
- MVVM
- CommunityToolkit.Mvvm
- SQLite
- Dapper

## Зависимости запуска

- Windows 10/11 с поддержкой `net10.0-windows10.0.19041.0`
- установленный .NET 10 Desktop Runtime
- для уведомлений в центре уведомлений Windows 11: установленный Windows App Runtime 1.8
- если Windows App Runtime 1.8 отсутствует или повреждён, Taskloom остаётся работоспособным, но локальные уведомления откатываются на fallback через tray balloon
- для audio metadata и cover art используется пакет `TagLibSharp`

## Архитектурные принципы

- Один WPF-проект на старте с логическим разделением по папкам.
- Строгое разделение UI, прикладной логики и работы с данными.
- Calendar-centered модель навигации и представления данных.
- Расширяемость под несколько типов записей без искусственных абстракций.
- Все пользовательские строки интерфейса должны идти через механизм локализации.
- Календарь должен оставаться главным визуальным и навигационным элементом основного окна.
- Цвета интерфейса должны развиваться через отдельный слой тем, а не через хаотичные локальные значения в XAML.

## Правила работы с Git и GitHub

- Рабочая ветка разработки: `dev`.
- Ветка `master` не используется как основная ветка активной разработки.
- `docs` являются частью проекта и должны входить в коммиты вместе с кодом, если затронуто поведение, архитектура, план или процесс.
- Корневой `README.md` является витринной страницей репозитория на GitHub и должен обновляться при значимых пользовательских, архитектурных или инфраструктурных изменениях.
- Перед коммитом нужно проверять состав staged-файлов, чтобы в коммит не попадал мусор IDE и локальные артефакты.

- Добавлена поддержка переключаемых цветовых схем через настройки приложения и WPF `ResourceDictionary`.
- Для задач в списке реализован быстрый переключатель статуса через интерактивный status chip с семантическими цветами темы.
- Chips и semantic palettes доведены до более согласованной системы: общая геометрия вынесена в ресурсы, а success/danger оттенки согласованы с характером тем.
- Главное окно получило кастомную title bar область в стиле приложения вместо стандартной системной шапки.
- Левая календарная панель упрощена до трёх рабочих зон: статус, календарь, навигация по дням.
- В редакторе события время начала и окончания выбирается точными селекторами `HH:MM:SS`, ручной ввод строк времени больше не используется.
- Карточка события показывает место, если оно было указано при создании или редактировании.
- Для событий добавлены статусы, цветные бейджи статуса, выбор времени напоминания и Windows App SDK notifications с fallback на системный tray balloon.
- Для задач добавлено собственное время напоминания на дату задачи; pending-задачи уведомляются через тот же notification transport.
- Для всех типов записей поддерживается несколько прикреплённых изображений; ресурсы записи хранятся в `%LocalAppData%\Taskloom\Records\<record-id>\images`, в редакторе их можно добавлять, удалять и менять порядок, а в списке дня они показываются grid-блоком миниатюр.
- Для всех типов записей поддерживается несколько аудиофайлов; ресурсы записи хранятся в `%LocalAppData%\Taskloom\Records\<record-id>\audio`, обложки — в `%LocalAppData%\Taskloom\Records\<record-id>\audio-covers`, а в карточке записи показывается playlist с play/pause, seek и открытием файла через системный обработчик.
- Для записей хранится persisted-время создания; в карточке оно показывается компактным muted-бейджем.
- Для аудиофайлов дополнительно читаются `album` и `genre`, если они есть в тегах; эти данные показываются компактно и не занимают заметное место при отсутствии.
- Для обрезаемых строк карточки добавлены hover-подсказки с полным текстом, чтобы не расширять layout по контенту.
- Для YouTube-ссылок в описании под карточкой записи показываются title и thumbnail preview; превью кешируется в каталоге записи, а при сетевой ошибке используется placeholder.
- Если `oEmbed` не отдал title, YouTube preview пытается взять title и description из публичной HTML-страницы видео как fallback без API-ключа: сначала через meta-теги, затем через `ld+json` и `ytInitialPlayerResponse`.
- Preview-карточка видео уже поддерживает `description` и `duration`; для YouTube эти поля заполняются при наличии бесплатного `TASKLOOM_YOUTUBE_API_KEY`, иначе автоматически скрываются.
- В редакторе записи есть опциональный флаг скрытия standalone video links при наличии preview; он выключен по умолчанию и влияет только на display-представление карточки, не меняя исходный текст заметки.
- Для записей выбранного дня теперь поддерживается persisted ручной порядок; карточки можно перетаскивать мышкой и переставлять внутри дня, а порядок сохраняется в SQLite.
- Для Twitch, VK Видео и RuTube уже добавлена классификация ссылок в общем pipeline, но отдельные providers enrichment пока остаются следующим шагом.
- Следующий приоритетный UX-этап проекта: полировка drag-reorder карточек и подготовка этой же основы под будущий `strip mode`, без перехода к свободному pixel-positioning.
- Описание записи в карточке автоматически распознаёт и открывает ссылки: URI со схемой (`http/https/ftp/tg/mailto/file` и другие), домены без схемы, email и IPv4-адреса.
- Главное окно при первом запуске открывается развёрнутым, а дальше запоминает последний размер и состояние через настройки приложения.
- Добавлены дополнительные темы: светло-серая светлая, графитовая, глубокая тёмная, Windows 11, Ubuntu, Windows 7, macOS, лягушачья зелёная, вулканическая огненная, космическая холодная и зимняя белоснежная.
- Вспомогательные окна переведены на кастомную title bar область в стиле приложения.
- Подтверждения удаления и опасных cleanup-режимов теперь показываются через собственное тематическое окно приложения вместо системного `MessageBox`.
- Контент карточек записей с малым количеством текста больше не центрируется по высоте рядом с более высокими карточками; порядок блоков карточки стабилизирован как `заголовок -> текст -> аудио -> изображения`.
- Выделение записи снимается кликом по пустым областям окна, а выбранная карточка подчёркивается утолщённой левой границей без артефактов на скруглениях.

- Для video links добавлен отдельный кэш preview в `%LocalAppData%\Taskloom\Records\<record-id>\link-previews` и metadata-файл `%LocalAppData%\Taskloom\Records\<record-id>\link-previews.json`.
- Окно настроек применяет язык, тему и политику очистки сразу при выборе; отдельная кнопка `Применить` убрана.
- Исправлены конкурентные сохранения `settings.json` и повторные каскадные apply-операции в окне настроек.
- Добавлена политика автоматической очистки старых записей при запуске: `никогда`, удаление всех записей старше `7 дней` или `1 месяца`, а также два более безопасных режима только для завершённых задач и прошедших событий.
- Добавлен tray mode: закрытие главного окна скрывает приложение в трей, реальный выход доступен через меню tray icon.
